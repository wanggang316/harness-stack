# 项目知识

长期文档帮助没有参与历史讨论的人理解系统并正确修改。按知识主题组织当前说明，按决定保留理由，按任务记录交付。文件按需创建，不要求每次修改产出文档。

## 三类记录

| 类别 | 回答的问题 | 维护方式 |
| --- | --- | --- |
| 当前知识 | 系统如何工作、承诺什么、如何操作 | 随相关变化原位更新 |
| 决策记录 | 在什么约束下为何这样选，接受什么代价 | 保留背景，明确有效状态与替代关系 |
| 交付记录 | 本次要改什么、进展如何、验证了什么 | 执行中更新，完成后关闭或归档 |

契约表示应当成立的规则，实现说明表示当前机制，两者冲突需要判断原因。实现、合并、部署和运行验证是不同状态；历史测试结果只证明当时版本和环境下的观察。

## 知识入口

沿用项目已有目录、语言与索引。没有约定时，可按需使用 `docs/README.md`、`docs/glossary.md`、`docs/architecture.md`、`docs/domains/`、`docs/adrs/` 和 `docs/runbooks/`。小项目可先用 README；不建立空目录或平行词汇表。

领域可以是业务领域、技术子系统或稳定能力，不要求对应 DDD 边界；已有的组件文档、子系统文档或包 README 可继续作为权威位置，不另建平行的 `docs/domains/`。领域文档是行为与边界的主要维护位置。全局架构说明跨模块关系，ADR 保存理由，runbook 保存可执行步骤。用链接连接证据和决定；同一项规则只有一个主要维护位置。

`AGENTS.md` 保留工作约束和条件式入口。例如修改认证时读认证领域文档，准备发布时读发布 runbook。历史记录不进入默认阅读路径。

## 内容原则与基本结构

严格约束职责范围、事实状态、知识归属和可发现性，章节按主题裁剪。可从“范围与职责、行为与不变量、交互与失败、实现形态、相关决定”开始；这些是覆盖问题，不是必须填齐的模板。领域页讲模型、规则与边界，不按代码逐项罗列。具体写作与放置规则见 [document 的知识放置指南](../skills/engineering/document/references/placement.md)。

当前知识对应所在代码版本，不自动表示已部署。设计阶段记录已确认的术语、决定和待更新的知识位置，不将未来行为写成当前实现。实现时同步更新对应知识；一次运行的验证结果留在交付记录。

## 变更生命周期

1. 开工时读取相关当前知识和有效决定；仓库修改在独立 worktree 的非 main 分支进行，文档和 Skill 同样适用。先讨论关键取舍，明确方向后将完整需求与设计决定整理为 spec ticket；普通改动可直接用任务描述。
2. spec 可直接实现，也可按需拆成可独立验证的子任务。子任务引用共同约束；没有父 spec 时补齐执行所需上下文。执行状态、偏差及验证证据放在任务或 PR。
3. 实现前识别受影响的知识位置；每个改变行为、架构或操作方式的实现步骤同步更新对应知识，不等单独的文档阶段。重要的新理由记录为 ADR，没有长期知识变化时说明无需更新。交付前按完整变更核对文档覆盖，评审时检查相关文档，包括未出现在 diff 中的页面；不因标题不同要求套用模板。
4. 交付时以实际证据更新任务状态，链接相关 PR、当前知识和 ADR。合并与部署按实际发生分别记录。复杂 RFC 可使用设计文件作为权威正文，ticket 链接它并承载讨论和状态，不维护两份相同正文。已有历史 proposal 保留背景，不要求迁移。

## 独立能力

- `grill-with-docs`：用户主动发起的分轮设计访谈，在讨论中记录已确认的术语与重要决定。
- `write-spec` / `to-spec`：把已讨论清楚的需求与设计写成 spec；`to-spec` 再把它发布为一张 spec Issue，不自动拆票。
- `write-tickets` / `to-tickets`：把 spec、plan 或会话拆成带依赖的执行任务；`to-tickets` 再把它们发布到 tracker。
- `document`：将已确认变化落实到最小的长期知识集合。
- `audit-docs`：检查准确性、可发现性和保留价值，修复有证据的问题。
- `domain-modeling`：在讨论中澄清概念并及时记录确定的术语和决定。

这些能力不构成强制流水线。日常开发可直接修订相关文档，审计也不要求存在 proposal 或历史 ticket。

## 保留与淘汰

优先保存业务语义、不变量、跨模块关系、不明显的决策理由、操作与恢复知识，以及难以重新发现的经验。普通调试经过、逐文件变更清单、易查询的配置值无需复制进长期知识。

删除内容前确认它没有独有的解释或历史价值；未知不等于错误。退役的当前说明退出当前入口，被替代的决定保留来源与替代指针。未解决的契约冲突明确报告，不以整理文档为由改变产品规则。

检验入口是否有效：新上下文能否找到某领域的概念、行为约束、修改影响和决策理由，而无需按时间重读交付历史。
