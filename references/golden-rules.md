# Golden Rules

harness-stack 的核心原则。所有 Skills 和 Agents 必须遵守。本版本以 1、2 两条为首要原则，与其他规则冲突时优先。

## 1. 原子性
- 一个 Skill 只负责一段单一、完整的职责，从输入到产出可独立完成
- 不预设前后由哪个 Skill 衔接：不写「之后交给 X」「先经 Y 打开」
- 前提不满足时停下告诉用户，不转交另一个 Skill

## 2. 自足，减少引用
- 引用其他 Skill、命令或它们的 `references/` 是可选的增强，不是运行依赖
- 去掉所有外部引用后，Skill 仍能正常运行：必需的步骤直接写进本 Skill（一两句话或一条命令）
- 本 Skill 自己的 `references/`、`scripts/` 不算外部引用
- 流程编排（如 commit → pr-open → pr-land）只写在 AGENTS.md 等导航文档里，不写进 Skill

## 3. AGENTS.md 是地图，不是手册
- 保持在 100-150 行以内
- 只包含导航信息，不包含详细内容
- 详细内容放在 docs/ 和 skills/ 中

## 4. 仓库知识即真理源
- 所有知识版本化在仓库中
- Agent 无法访问的信息 = 不存在
- 文档与代码共同演进

## 5. 一切都是 Skill 或 Subagent
- 没有外部 CLI 工具
- 初始化、验证、评分都是 Skills
- 专业判断交给 Subagents

## 6. 渐进式披露
- 短入口 → 按需加载深度内容
- 避免上下文污染
- 每个文件只包含必要信息

## 7. 证据优先
- 每个验证步骤需要具体证据
- "我检查了" 不够，需要 "我运行了 X，结果是 Y"
- 退出标准必须可验证

## 8. 反合理化
- 每个 Skill 预先列出 Agent 可能的借口
- 提供反驳和正确做法
- 防止 Agent 偷懒跳步

## 9. 平台无关
- Skills 不硬编码框架命令
- 读取项目配置，不做假设
- 询问用户一次，持久化答案

## 10. 增量交付
- 薄垂直切片优于水平分层
- 每个切片都是可工作的功能
- 小步快跑，频繁验证

## 11. 机械化执行
- 能自动化的不靠文档
- 用工具验证结构和质量

## 12. 自举能力
- harness 可以用自己的 Skills 改进自己
- 仓库内的 `/skill-create`（`.claude/skills/skill-create/`）维护 Skills
- 自身质量可验证

## 13. 修复环境，不修复提示
- 当 Agent 反复犯错，改善环境而非重复提示
- 添加 linter 规则、更新 golden rules
- 让正确的做法成为最容易的做法

## 14. 上下文是稀缺资源
- 每个加载到 Agent 上下文的内容都有成本
- 只加载当前任务需要的信息
- 支持文件按需加载，不预加载
