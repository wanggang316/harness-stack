# Golden Rules

harness-stack 的核心原则。所有 Skills 和 Agents 必须遵守。本版本以 1、2 两条为首要原则，与其他规则冲突时优先。

## 1. 原子性
- 一个 Skill 只负责一段单一、完整的职责，从输入到产出可独立完成
- 不预设前后由哪个 Skill 衔接：不写「之后交给 X」「先经 Y 打开」
- 前提不满足时停下告诉用户，不转交另一个 Skill

## 2. 自足与专业方法复用
- Skill 自己明确目标、所需上下文和完成条件；可以在职责内调用专业 Skill，例如 implement 使用 tdd
- 引用写清触发条件、所需方法及结果如何用于当前任务，共享方法保持一个权威版本
- 依赖不可用时，能维持完成标准就采用简短的本地方法；不能时报告缺少的能力及受影响步骤，不假装已执行
- 本 Skill 自己的 `references/`、`scripts/` 不算外部引用
- 完整生命周期的导航（如 commit → pr-open → pr-land）放在 AGENTS.md；职责内的方法调用不属于额外的生命周期任务，也不扩大授权

## 3. AGENTS.md 是地图，不是手册
- 保持在 100-150 行以内
- 只包含导航信息，不包含详细内容
- 详细内容放在 docs/ 和 skills/ 中

## 4. 仓库知识即真理源
- 所有知识版本化在仓库中
- Agent 无法访问的信息 = 不存在
- 文档与代码共同演进

## 5. 一切都是 Skill 或 Subagent
- 没有外部 CLI 工具
- 初始化、验证、评分都是 Skills
- 专业判断交给 Subagents

## 6. 渐进式披露
- 短入口 → 按需加载深度内容
- 避免上下文污染
- 每个文件只包含必要信息

## 7. 证据优先
- 每个验证步骤需要具体证据
- "我检查了" 不够，需要 "我运行了 X，结果是 Y"
- 退出标准必须可验证

## 8. 反合理化
- 以明确的完成条件和实际证据防止提前结束
- 对观察到的重复失败说明目标行为及原因，避免为假想借口堆叠警告
- 能由类型、测试或工具检查消除的失败优先用结构约束

## 9. 平台无关
- Skills 不硬编码框架命令
- 读取项目配置，不做假设
- 询问用户一次，持久化答案

## 10. 增量交付
- 薄垂直切片优于水平分层
- 每个切片都是可工作的功能
- 小步快跑，频繁验证

## 11. 机械化执行
- 能自动化的不靠文档
- 用工具验证结构和质量

## 12. 自举能力
- harness 可以用自己的 Skills 改进自己
- 仓库内的 `/skill-create`（`.claude/skills/skill-create/`）维护 Skills
- 自身质量可验证

## 13. 修复环境，不修复提示
- 当 Agent 反复犯错，改善环境而非重复提示
- 添加 linter 规则、更新 golden rules
- 让正确的做法成为最容易的做法

## 14. 上下文是稀缺资源
- 每个加载到 Agent 上下文的内容都有成本
- 只加载当前任务需要的信息
- 支持文件按需加载，不预加载
